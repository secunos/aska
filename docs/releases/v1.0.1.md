# Aska v1.0.1 — release record

**Tag:** `v1.0.1` (annotated, by the release owner `secunos`; the tag commit is the one built, `28511d4`). **Built:** 7 October 2026, 10:41 UTC. **Status:** patch release on top of 1.0.0 — one command-line fix, nothing else changed. **Not independently audited and not legally reviewed** — see `SECURITY.md`, the User Guide §1 and §9.

## What changed since 1.0.0

- **Command-line client:** when the program reading its output goes away early (`aska verify | head -1`, `… | grep -q …`), `aska` now stops quietly with exit status 141 — the status a shell reports for a command ended by SIGPIPE — instead of aborting with status 134 and a "failed printing to stdout: Broken pipe" message. The command unwinds normally, so the Session and every buffer are still wiped on the way out. Diagnostics on a closed standard error are dropped instead of aborting. New regression test (`closed_stdout_exits_141_quietly`: `verify`, `doctor`, and `send` with the output closed in the middle of the hand-over).
- **Documents:** the User Guide and Relay Operator Guide name the 1.0.1 files; the User Guide lists exit status 141. The 1.0.0 release record gained its publication section.
- **Not changed:** the graphical client's behaviour, `aska-core`, the wire protocol, the Block Format, the relay's code (only its version string), the installer, the Tor configuration and the systemd unit. Dependencies identical (same `VENDOR-HASH`).

**Who should upgrade:** anyone who scripts the command-line client. For everyone else 1.0.1 behaves exactly like 1.0.0. Relay operators do not need to upgrade.
