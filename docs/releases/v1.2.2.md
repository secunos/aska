# Aska v1.2.2 — release record

**Tag:** `v1.2.2` (annotated, by the release owner `secunos`; the tag commit is the one built, `8a44a06`). **Built:** 2026-10-17 16:56 UTC. **Status:** patch release on top of 1.2.1 — **brand 2.0** (the *ASKA Brand Guidelines 2.0*, decided 17 October 2026, supersede brand 1.0 shipped in 1.2.1 the same day). **No change to any behaviour, format, protocol, rule or gate.** Not independently audited and not legally reviewed, as every release before it.

## What changed since 1.2.1

1. **The icon.** `org.aska.Aska` is the **Fade mark** — a 4 × 4 grid of dots shrinking from the lower-left to the upper-right — in paper on an ink tile; the `hicolor` theme ships PNGs 16–512 (3 × 3 master at 16–24 px, a heavier grid at 32–48 px), the scalable SVG and a symbolic SVG. `install.sh` and the User Guide's removal command are unchanged (same file names).
2. **The palette.** The **Graphite** colours replace Nordic calm: black and white — window `#FFFFFF`/`#0B0B0B`, surface `#F5F5F5`/`#161616`, text `#111111`/`#F2F2F2`, muted `#666666`/`#9A9A9A` — with the accent now ink (the main button is black on light, white on dark) and colour only for states (info, success, warning, danger). Every text colour passes 4.5:1. The sheets (`crates/aska-gui/brand/aska.css`, `aska-dark.css`) also make every control a 4 px rectangle and cards 8 px: there are no pill buttons any more.
3. **The lockup, without a slogan.** The Home screen shows the mark and the name **ASKA** (Jost Medium capitals as outlines) and nothing else: the slogan of 1.2.1 is gone everywhere — Home, the launcher entry (its description is again "Send a note that leaves nothing behind"), the CLI's `--help` headline ("ASKA — secure notes that leave nothing behind."), both locales. The header block keeps its 84 px, with the lockup drawn at the guidelines' 64 px mark height centred inside it, so the buttons below keep their positions and the coordinate-driven GUI gates pass unchanged. The black lockup is used on light grounds and the white one on dark; the two images share one geometry, so switching the colour scheme changes nothing in the layout.
4. **Names.** The window title is **ASKA** on every screen (it was `aska`; it still never names the screen or the note, Client Design §5.7) and the desktop entry is **ASKA**. The command, the file names and the application id stay lowercase (`aska`, `aska-gui`, `org.aska.Aska`). The GUI gate scripts look for the new title.
5. **Banners and the Tor state.** Every doctor banner now starts with its word — *Refused:*, *Warning:*, *Note:* (Swedish *Avvisat:*, *Varning:*, *Obs:*) — in the state colour on its tinted ground, so colour is never the only signal; the footer's Tor state is an 8 px dot in the state colour (green connected, amber checking or no circuit, red blocked or down) followed by the word as before. The doctor's findings, their texts and their semantics are unchanged (`aska-core`); only the GUI's presentation changed.
6. **The repository.** README lockup (black/white aware), `docs/brand/README.md` rewritten for 2.0, SECURITY.md status. The 1.0 lockup files are removed; the kit's `aska-tokens.json` 2.0 is the colour source of truth.

Nothing is read from disk at run time for any of this: the colour sheets and the lockup images are compiled into the binary. No font is installed or needed. `aska --version` → 1.2.2.

**Compatibility.** Identical to 1.2.0 and 1.2.1 in everything but appearance; notes, keys, Receiving Keys, pad pages, cards and profiles are unaffected; the relay is unchanged (operators need not upgrade; `aska-drop` 1.2.2 is a rebuild).

## Deviations and known issues

Those of 1.2.0 carry unchanged (camera path and PHYSICAL source unvalidated on hardware; paper rules stated, not enforced; printing leaves records; live CUPS path not exercised; two `lru` advisories; no container build, no Rekor entry, no reviews). Client Design v0.8 §5.1 still describes the Home title as "the name" with a tagline, and §5.7 the window title as `aska` — to be folded at the next re-issue (v0.9, with the mobile design). The paper memory gate's first run on the 2.0 build failed at its first click: at the gate's 1068 px window the 280 px Home buttons span x 394–674 and the gate clicked x = 380, which had hit the former 320 px button by six pixels; the gate now clicks the button's centre (x = 534) and all three GUI gates pass. **The tag-push CI run of `v1.2.2` is red** (18 October, after publication): the `test` job failed at `scripts/no-file-writes-lib.sh aska-paper`, which runs the paper crate's test binary under `strace`. The failing test was one of the crate's statistical self-tests, which drew their sample from the OS random generator and therefore carried a small false-alarm probability on every run (about 0.3 % per health-test call, the health tests being deliberately strict at the 0.1 % level); the same source had passed `cargo test --workspace` two steps earlier in the same job and on every run before. The release artefacts are unaffected — tests are not part of the shipped binaries and the paper crate's code is unchanged since 1.2.0. Fixed on `main` after the tag by feeding those tests a fixed SHAKE256 stream (`entropy::test_bytes`) with the same statistics and a fixed verdict (margins: χ²₉ 2.9 of 27.9, χ²₉₉ 63 of 148, repeats z −1.2 of 3.3, longest run 5 of 8). The next run on `main` then failed in the same way one step earlier, in the CLI tests: a dice booklet of 400 digits was refused by the pad's own health tests (χ²₉ = 34.1) — which is the product working as specified (DC-04 §8: strict tests on fresh digits, about one booklet in three hundred refused, the user makes another), but a CI run generates some ten booklets and so failed a few times in a hundred. The CLI test harness and the GUI paper gate now do what a user does — make another booklet, up to three attempts — while the binaries keep no deterministic or lenient mode. A third red run (19 October, the same `strace` gate; the gate discarded the test output, so which test failed is not known) led to a sweep of every test in the paper crate that still used fresh randomness: the two booklet tests retry a by-design refusal like the harness, and the Block-card test — which asked the independent decoder to find four version-40 codes on one sheet, and which a probe showed missing one code on about one random sheet in thirteen while single cards decoded 160 of 160 through the clients' own entry point — now uses a fixed Block and set id and additionally decodes each card alone, as a camera does. The gate prints the test output when it fails. The tag is not moved. The guidelines' typography (Jost for headings, JetBrains Mono for fingerprints) is not applied inside the client, which uses the platform's interface and monospace fonts, as the guidelines themselves prescribe for the `ui` and `mono` roles; the brand faces appear only in the outlined logo files.
