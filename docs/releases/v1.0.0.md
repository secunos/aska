## Deviations and known issues

1. **Superseded first candidate.** A first signed build of the same version (tarball `b59bf087…de66`) embedded 70 build-machine paths in `aska-gui` (dependency-source panic locations): `package-gui.sh` did not pass `--remap-path-prefix` to the GUI build. Fixed in the packaging script before publication, tag moved locally, rebuilt and re-signed; the first candidate was never published. The relay and CLI were byte-identical in both builds.
2. **Not built in the release container** (see Build).
3. **No Rekor entry.**
4. **Known issue, fixed in 1.0.1:** the command-line client aborts (exit 134, "failed printing to stdout: Broken pipe") instead of exiting quietly when its standard output is closed early, e.g. `aska verify | head -1`. No data is involved and core dumps are disabled; cosmetic.
5. **Owner decision:** released without the external security review and the legal review (release checklist §4 and §5 waived for 1.0.0; open for the next release).

## Changes found and fixed on the way to this release (6 October 2026)

- Receiving-key matching did a few microseconds of extra work on a match (locking the found key, deriving its label) — now identical work on a match and a miss (`Session::match_records_with_seed`); measured hit − miss over 10 000 rounds: +4.9 µs before, +0.4 / +0.15 µs (within noise) after.
- The write gates now refuse to judge an unreadable trace (Aska makes itself non-dumpable; a non-root tracer sees no paths) and run as root in CI.
- The seed-matching timing test compared two different keys instead of a hit with a miss; corrected.
- GUI gates wait for the window instead of a fixed delay and keep a screenshot on failure.
